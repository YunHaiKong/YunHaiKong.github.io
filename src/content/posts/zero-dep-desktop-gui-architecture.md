## 桌面端 GUI 的两难抉择

为 AI 智能体开发桌面客户端，很多人的第一反应通常是：
1. **方案 A：Electron / Tauri / VS Code 插件**
2. **方案 B：PyQt / PySide / Tkinter**

然而，当我们把视线拉回到真实的 **Windows 7 专网客户机**（通常是配备 4GB 内存、机械硬盘、甚至老旧二代酷睿处理器的老爷机）时，这些主流方案暴露出致命缺陷：

- **Electron**：包体积动辄 150MB+，启动内存占用 300MB+，且从 Electron 19 开始彻底放弃 Win7。此外老机器的陈旧显卡驱动在遇到 GPU 硬件加速时极易引发蓝屏或花屏崩溃。
- **PyQt / PySide**：C++ 依赖深、动态链接库多，极易踩到 Windows 7 未知 DLL 缺失的雷区，且分发体积巨大。
- **Tkinter**：原生组件样式极其老旧、不支持现代排版流式渲染，且在嵌入式 CPython 中缺失 Tcl/Tk 运行时。

## 破局之道：“本地 HTTP + 原生前端 + 系统默认浏览器”

经过慎重权衡，我们设计了一套**极简而优雅的零依赖桌面交互架构**：

```text
[openlaoke_gui.cmd] 
       ↓ 
[openlaoke_gui.py] (基于标准库启动轻量本地 HTTP 服务，端口默认 8765)
       ↓
[系统默认浏览器打开] (如 Chrome 109 / Edge / Firefox)
       ↓
[openlaoke_gui.html] (纯原生 HTML5 + CSS3 + 现代 JavaScript，单文件内嵌)
       ↓ (WebSocket / SSE HTTP 长连接)
[openlaoke_gui_worker.py] (驱动后台智能体 Agent 执行流)
```

### 这一设计的巨大优势：
1. **真正的零依赖、零构建**：没有 `npm`、没有 Webpack、没有 Vite，也没有庞大的 `node_modules`。前端单文件交付，修改即生效。
2. **极速启动与低资源占用**：Python 后台常驻内存不到 40MB，浏览器只是打开一个标签页。
3. **天然拥抱现代化排版**：即使是 Windows 7 上的最终版 Chrome（Chrome 109），也原生完整支持 CSS Flexbox、Grid、现代 Fetch API 与富文本代码高亮。

## 落地过程中的三个“真产品坑”

在静态代码审计和单测时一切看似顺利，但走通完整的端到端图形界面时，三个隐藏极深的交互 Bug 接踵而至。

### 1. 技能（Skill）选择器列表全为空白
- **现象**：GUI 界面打开后，左侧的内置技能下拉菜单空空如也。
- **真因**：上游代码在查找技能目录时，粗暴地硬编码了路径匹配 `python/site-packages/openlaoke/skills`；但在我们构建的便携式目录结构中，实际安装路径为 `python/Lib/site-packages/openlaoke/skills`。
- **解法**：重构路径发现逻辑为 `bundled_skill_root()`，利用 Python 标准库的 `importlib.util.find_spec("openlaoke")` 进行**动态元数据定位**，既避免了执行模块导致提前冻结全局配置，又完美自适应各种目录变体。

### 2. 发送对话后界面永远“转圈”，无任何回复
- **现象**：用户在聊天框输入并回车，状态显示正在生成，但界面一片死寂。
- **真因**：前端与上游模型交互默认开启了流式模式（`stream: True`），前端解析器只认服务端发送事件（Server-Sent Events, SSE）格式——即必须按行解析 `data: {"text": "..."}\n\n` 格式帧，并在结束时接收 `[DONE]` 标识。而此前的单元测试 Mock 桩只返回了普通的一次性 JSON 字典，导致前端状态机永远在等待下一帧数据。
- **解法**：在交互网关层重构流式响应协议，标准化包装 SSE 分块传输机制。

### 3. 工作区（Workspace）早期路径显示异常
- **现象**：智能体在最初启动的几秒内，前端顶部的工作区路径显示为空或占位符，直到首次执行命令后才刷新。
- **解法**：在 Agent 初始化构造函数中显式注入声明期工作区（`declared_workspace`），做到启动瞬时即完成元数据与前台 UI 的无缝同步。

## 经验与总结

在资源受限或历史遗留系统中，“**奥卡姆剃刀原则：如无必要，勿增实体**”是最高准则。

放弃追求大而全的重型框架，转而利用操作系统自带的成熟浏览器作为视窗外壳，用最纯粹的 HTTP 协议做前后端解耦，不仅大幅降低了打包分发体积，更规避了无数底层动态链接库的兼容性风险。
